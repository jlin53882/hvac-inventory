# 🔐 安全性維護指南（hvac-inventory）

> 本文件給後續維護者（人類或 AI agent）使用——系統怎麼跑、怎麼測、**有哪些安全性規則要遵守**。
> 最後更新：2026-09-15（Google Calendar 同步可靠性、錯誤遮罩與維護測試同步）

## 一、系統概覽

| 項目 | 內容 |
|---|---|
| 架構 | FastAPI + SQLite（單檔 `inventory.db`）+ 原生 JS 前端（`static/`） |
| 後端入口 | `main.py`（路由分散在 `app/routes/*.py`，商業邏輯在 `app/services/`） |
| 資料庫 | SQLite，`app/database.py` 管理 schema + init |
| 前端 | `static/index.html` + `static/js/`（render / modals / utils），無框架 |
| 使用者認證 | `app/services/auth.py`（PBKDF2 密碼 hash + session token + per-IP rate limit） |
pytest（**1492 條、33 檔**；以本輪 `pytest --collect-only -q` 為準，分組執行與維護見 `docs/單元測試維護文件.md`）

## 二、啟動與測試

```bash
# 啟動（預設 port 8000；本機同時跑多個實例時改用 8002 等避免衝突）
.venv/Scripts/python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
# 或直接跑 start.bat

# 測試（Windows MSYS bash 需清掉 PYTHONPATH 避免污染；分組/觸發條件見 docs/單元測試維護文件.md）
./scripts/run-tests.sh all            # 全量（並行建議: pytest tests/ -n auto）
```

> ⚠️ 本機 `PYTHONPATH` 可能指向其他 venv（如 hermes），跑測試/起 server 一律加 `env -u PYTHONPATH`。
> ⚠️ 背景 uvicorn 用 `Ctrl+C` 關掉後，Windows 常殘留 python 子進程佔住 port——用 `netstat -ano | grep :8000` 找 PID 再 `taskkill /F /PID <pid>`。

## 三、安全性規則（⚠️ 改動前必讀）

以下規則為 2026-08-10 安全性修復（PR #1）訂立，**不要弱化或繞過**：

| 規則 | 內容 | 相關檔案 |
|---|---|---|
| 密碼 policy | 至少 8 碼 + 大寫 + 小寫 + 數字 | `app/routes/users.py::_check_pw`（權限頁新增帳號表單同步提示） |
| 輸入驗證（Pydantic） | qty ≥ 0（StockItem）、low_stock ≥ 0（ItemUpdate）、StockoutUpdate qty > 0 | `app/models.py`（Field ge=0 / gt=0） |
| 前端必填驗證 | 新增品項 brand/code/location 必填；行事曆 client_name/date 必填；所有表單送出前 toast 提示 | `static/js/modals/add.js`、`calendar.js` |
| 照片前端驗證 | 副檔名白名單（.jpg/.jpeg/.png/.webp）+ 10MB 大小上限（送出前檢查） | `static/js/modals/photo.js` |
| 密碼 policy 即時提示 | 新增/批次/重設帳號 → `pwPolicyMsg()` 前端即時顯示政策 | `static/js/perms.js` |
| 照片與媒體存取 | 新照片由 `app/services/file_storage.py` 建立 `file_assets` metadata，保留 original、preview、thumbnail；`/uploads/<id>.jpg` 舊 URL 只回傳登入後 preview，`/media/{asset_id}/{variant}` 全部需登入；original 下載強制 `Content-Disposition: attachment` | `app/services/file_storage.py`、`app/routes/photos.py`、`main.py` |
| 媒體檔案安全 | 副檔名白名單之外仍檢查圖片內容/PDF magic bytes；圖片 load 前檢查 40MP；DB 內相對路徑經 uploads root traversal guard；照片含個資，不得 commit/push | `app/services/file_storage.py`、`scripts/audit_file_storage.py` |
| 壓縮與快取 | GZip 只處理文字資源，二進位圖片/PDF 不壓縮；static 資源由 mtime 產生 immutable 版本號，HTML no-cache | `app/middleware.py`、`main.py` |
| 登入 rate limit | per-IP 失敗登入：60 秒窗內 10 次 → 429（成功登入自動清空；帳號級鎖定另有 5 次/15 分鐘） | `app/services/auth.py` |
| session 清理 | 停用帳號 / 重設密碼 → 立即刪除該使用者所有 session | `app/routes/users.py` |
| cookie | HTTPS 連線才設 `Secure` flag（本機 HTTP 不設，避免登入失效） | `app/routes/auth.py` |
| 安全 headers | 所有回應帶 `X-Frame-Options: DENY` / `X-Content-Type-Options: nosniff` / `Referrer-Policy: no-referrer` / CSP（`frame-ancestors 'none'` + 同源 `connect-src`） | `main.py::security_headers_middleware` |
| Google Calendar 同步錯誤 | queue、appointment API 與同步/刪除/backfill/webhook log 只使用安全錯誤分類，不保存或回傳 credential path、token、secret 或 raw traceback | `app/services/gcal_sync.py`、`app/routes/appointments.py`、`app/routes/gcal_keys.py`、`app/services/sync_scheduler.py` |
| 照片不進 git | `.gitignore` 有 `static/uploads/`（照片含個資，禁止 commit/push） | `.gitignore` |

**XSS 守則**：任何把使用者輸入渲染進 HTML 或 JS 的位置，必須過 `esc()`（HTML）/ `jsStr()`（JS literal，`static/js/utils.js`）——新增渲染點前先看 utils.js 有沒有現成 helper。

## 四、資源版本號機制（cache-busting）

- 原始 HTML **不寫** `?v=N`（刻意保持乾淨）。
- 對外服務時，`main.py::_versioned_html()` 依**檔案 mtime** 自動為每個 static 資源帶版本號。
- **改 JS/CSS/圖片後：什麼都不用做**，存檔即生效（mtime 變 → 版本號自動變）。不要手動加 `?v=N`。

## 六、常見維護操作

| 操作 | 作法 |
|---|---|
| 新增使用者 | 登入 admin → topbar「👥 帳號與權限」→ ＋新增帳號（單一/批次，密碼須符合 policy） |
| 改密碼 | admin：topbar「⚙️ 設定」→ 修改密碼（2026-08-16 起）；重設密碼後該使用者所有舊 session 立即失效（需重新登入） |
| 帳號被鎖 | 等 15 分鐘（帳號級）或確認不是 IP 級 rate limit 誤鎖（清 `_ip_fail:*` 記憶） |
| 照片讀不到 | 確認已登入、`file_assets` metadata 與 `static/uploads/` 內 original/preview/thumbnail 是否存在；可執行 `python scripts/audit_file_storage.py` 檢查 checksum、missing、orphan |
| 備份 | 複製 `inventory.db` + `static/uploads/`（照片）。⚠️ **2026-08-14 起 DB 已開 WAL 模式**：直接 `cp inventory.db` 會漏掉仍在 `-wal` 檔的最新資料——備份前先 `sqlite3 inventory.db "PRAGMA wal_checkpoint(TRUNCATE)"`（把 WAL 併回主檔），或改用官方安全備份 `sqlite3 inventory.db ".backup inventory.db.bak-<日期>"`（WAL 下也含 -wal 內容） |
| 版本號異常 | 確認 HTML 原始檔沒手動 `?v=N`（會被 `_versioned_html()` 覆蓋） |

# 🔐 安全性維護指南（hvac-inventory）

> 本文件給後續維護者（人類或 AI agent）使用——系統怎麼跑、怎麼測、**有哪些安全性規則要遵守**。
> 最後更新：2026-08-11（Phase 2-5 安全更新）

## 一、系統概覽

| 項目 | 內容 |
|---|---|
| 架構 | FastAPI + SQLite（單檔 `inventory.db`）+ 原生 JS 前端（`static/`） |
| 後端入口 | `main.py`（路由分散在 `app/routes/*.py`，商業邏輯在 `app/services/`） |
| 資料庫 | SQLite，`app/database.py` 管理 schema + init |
| 前端 | `static/index.html` + `static/js/`（render / modals / utils），無框架 |
| 使用者認證 | `app/services/auth.py`（PBKDF2 密碼 hash + session token + per-IP rate limit） |
| 測試 | `tests/`（pytest，目前 **237 條**，2026-08-11） |

## 二、啟動與測試

```bash
# 啟動（預設 port 8000；本機同時跑多個實例時改用 8002 等避免衝突）
.venv/Scripts/python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
# 或直接跑 start.bat

# 全量測試（Windows MSYS bash 需清掉 PYTHONPATH 避免污染）
env -u PYTHONPATH .venv/Scripts/python.exe -m pytest tests/
```

> ⚠️ 本機 `PYTHONPATH` 可能指向其他 venv（如 hermes），跑測試/起 server 一律加 `env -u PYTHONPATH`。
> ⚠️ 背景 uvicorn 用 `Ctrl+C` 關掉後，Windows 常殘留 python 子進程佔住 port——用 `netstat -ano | grep :8000` 找 PID 再 `taskkill /F /PID <pid>`。

## 三、安全性規則（⚠️ 改動前必讀）

以下規則為 2026-08-10 安全性修復（PR #1）訂立，**不要弱化或繞過**：

| 規則 | 內容 | 相關檔案 |
|---|---|---|
| 密碼 policy | 至少 8 碼 + 大寫 + 小寫 + 數字 | `app/routes/users.py::_check_pw`、`static/js/modals/users.js::pwPolicyMsg` |
| 照片存取 | 照片存 `static/uploads/<item_id>.jpg`；**公開路徑 `/static/uploads/*` 一律 404**（`_StaticWithoutUploads`）；登入者走 `/uploads/<id>.jpg`（`require_login` + 檔名白名單 `\d+\.jpg` 防路徑穿越） | `main.py` |
| 登入 rate limit | per-IP 失敗登入：60 秒窗內 10 次 → 429（成功登入自動清空；帳號級鎖定另有 5 次/15 分鐘） | `app/services/auth.py` |
| session 清理 | 停用帳號 / 重設密碼 → 立即刪除該使用者所有 session | `app/routes/users.py` |
| cookie | HTTPS 連線才設 `Secure` flag（本機 HTTP 不設，避免登入失效） | `app/routes/auth.py` |
| 安全 headers | 所有回應帶 `X-Frame-Options: DENY` / `X-Content-Type-Options: nosniff` / `Referrer-Policy: no-referrer` / CSP（`frame-ancestors 'none'` + 同源 `connect-src`） | `main.py::security_headers_middleware` |
| 照片不進 git | `.gitignore` 有 `static/uploads/`（照片含個資，禁止 commit/push） | `.gitignore` |

**XSS 守則**：任何把使用者輸入渲染進 HTML 或 JS 的位置，必須過 `esc()`（HTML）/ `jsStr()`（JS literal，`static/js/utils.js`）——新增渲染點前先看 utils.js 有沒有現成 helper。

## 四、資源版本號機制（cache-busting）

- 原始 HTML **不寫** `?v=N`（刻意保持乾淨）。
- 對外服務時，`main.py::_versioned_html()` 依**檔案 mtime** 自動為每個 static 資源帶版本號。
- **改 JS/CSS/圖片後：什麼都不用做**，存檔即生效（mtime 變 → 版本號自動變）。不要手動加 `?v=N`。

## 五、檔案結構速覽

```
main.py                  # 入口 + 安全 headers + 版本注入 + 照片保護 endpoint
app/config.py            # 路徑設定（UPLOAD_DIR / DB_PATH / EXPORT_DIR）
app/database.py          # SQLite schema + 連線
app/services/auth.py     # 認證、session、rate limit、admin 初始化
app/routes/              # auth / users / items / stockout / kits / stocktake / stats / export / photos / lookup
static/js/utils.js       # esc() / jsStr() / 共用工具
static/js/render/        # inventory / stocktake / kits 等畫面渲染
static/js/modals/        # 新增/編輯 modal（users / kit 等）
tests/                   # pytest（132 條，含安全性回歸測試）
```

## 六、常見維護操作

| 操作 | 作法 |
|---|---|
| 新增使用者 | 登入 admin → 使用者管理 → 新增（密碼須符合 policy） |
| 改密碼 | 重設密碼後該使用者所有舊 session 立即失效（需重新登入） |
| 帳號被鎖 | 等 15 分鐘（帳號級）或確認不是 IP 級 rate limit 誤鎖（清 `_ip_fail:*` 記憶） |
| 照片讀不到 | 檢查檔案是否在 `static/uploads/<id>.jpg`、是否登入、檔名是否純數字 |
| 備份 | 複製 `inventory.db` + `static/uploads/`（照片） |
| 版本號異常 | 確認 HTML 原始檔沒手動 `?v=N`（會被 `_versioned_html()` 覆蓋） |

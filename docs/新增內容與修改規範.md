## 一、檔案放哪裡（結構地圖）

### 後端

| 新增內容 | 放哪裡 | ⚠️ 不要放 |
|---|---|---|
| API 端點 | `app/routes/<功能檔>.py`（items / stockout / kits / stocktake / units / stats / export / lookup / photos / appointments / **movements** / **service_types** / users / auth） | 不要塞進 main.py |
| 請求/回應 model | `app/models.py`（**全部集中**，2026-08-16 收攏 9 個） | ❌ 不要內嵌在 route 檔（改 model 要去找定義在哪） |
| HTTP middleware | `app/middleware.py`（cache_control / csrf_origin / security_headers） | ❌ 不要寫在 main.py |
| DB schema / migration | `app/database.py` 的 `_exec_init()`（CREATE TABLE + PRAGMA 檢查 ALTER 模式） | — |
| 純邏輯 helper | `app/services/`（auth / report / safety 共用安全 helper）或 route 檔內 `_` 前綴私有函式 | 同語意 helper 已有共用版就 import，勿再私寫一份 |
| 新功能找不到現成 route 檔 | **開新檔**（如 movements.py 先例），且 **main.py 兩處都要加**：① L29 import 行 ② for 迴圈 tuple（漏一處 = NameError，2026-08-16 v4 pro 審查 Tier A） | ❌ 不要「順手放進最近的檔」 |

### 前端

| 新增內容 | 放哪裡 | ⚠️ 注意 |
|---|---|---|
| 頁籤畫面 | `static/js/features/<功能>/page.js`（或依職責拆成 list / filters / history…） | ES module（issue #39）：用 `import` 取得依賴、`export` 給別的模組用；單檔 > 400 行或混多職責就拆 |
| 彈窗 / modal 邏輯 | `static/js/features/<功能>/<name>-modal.js` | 獨立檔，勿併入畫面檔 |
| 跨頁共用（工具、API、登入狀態） | `static/js/core/`；共用畫面元件 `static/js/components/` | 依賴方向 pages → features → components → core：core 不可 import components / features / pages；components 不可 import features / pages；features 不可 import pages（`tests/test_frontend_module_boundaries.py` 強制，無白名單；core / components 也不可落在 import 循環內）。core 需要觸發 feature 行為時由頁面進入點傳 callback（例：`initBottomsheet(() => switchTab(...))`），元件需要業務判定時由呼叫端傳入（例：`renderSharedProductStatusItem(item, { status })`）。會呼叫多個 feature 的流程放 features（例：`features/shell/data-refresh.js`、`features/notifications/center.js`） |
| 會被其他模組改寫的狀態 | 全站：`core/state.js` 的 `appState`；單一功能：`features/<功能>/state.js` 的 `<功能>State` | ES module 的 import 綁定唯讀，**不可**在別的模組直接 `x = …`；只在本模組用的變數就留在本模組 |
| inline handler（`onclick="…"`） | 寫成 `命名空間.函式(…)`，例如 `Inventory.openAddModal()` | 命名空間由 `static/js/pages/<頁>.js` 掛到 `window`；新增 handler 函式要 `export` 並加進該頁進入點的 `window.<命名空間>` |
| 模組載入時要做的事（綁事件、初始化） | 包成 `export function init<名稱>()`，由頁面進入點依序呼叫 | 模組頂層只放宣告，import 時不得有副作用 |
| 顏色 / 字級 / 字重 / 圓角 / z-index | `static/css/0-tokens/tokens.css` 的 `:root` 變數 | 其他檔一律 `var(--c-*)` / `var(--fs-*)` / `var(--fw-*)` / `var(--r-*)` / `var(--z-*)`，寫死色碼或數值會被架構測試擋下 |
| 按鈕 | `class="btn btn--<變體> btn--<尺寸>"`，外觀只在 `3-components/button.css` | 變體：primary（每區最多一個）/ secondary / ghost / danger / prepare / out / on-dark；尺寸 sm / md；頁面 CSS 只能調位置、寬度 |
| 篩選 / 頁籤 / 分段切換 | `class="chip"`（膠囊）或 `class="chip chip--seg"`（方角），選取加 `.is-active`；外觀只在 `3-components/chip.css` | 同上 |
| 跨頁共用元件（modal、表格、卡片…） | `static/css/3-components/<元件>.css`（`@layer components`） | 改這裡 = 全站生效；視覺測試會列出受影響畫面 |
| 版面骨架（側欄、頂欄） | `static/css/2-layout/` | — |
| 單一頁面專用樣式 | `static/css/4-pages/<頁>.css`，每個選擇器以 `[data-page="<頁>"]` 開頭（`@layer pages`） | 不得寫內嵌 `<style>`；modal 也要加頁面範圍 |
| 小工具（間距、顯示、文字色） | `static/css/5-utilities/utilities.css`（`u-*`） | HTML 只允許 `style="display:none"`；顏色類以 token 命名（`u-text-muted`、`u-bg-surface-2`），不可用色碼命名 |
| JS 產生的 HTML（render / modals） | 外觀寫成 class 放在對應的 CSS 檔 | 不可寫 `style="color:#…;font-size:…"`；inline 只能是 `display:none` 或 `${資料值}` |
| 不屬於 `.btn` / `.chip` 的專用按鈕（數量 ±、關閉 ✕、KPI 卡…） | 在 `tests/button_contract.json` 登記 class | 沒登記的一般按鈕會被靜態與瀏覽器測試擋下 |
| 新 JS 檔 | 從用到它的模組 `import`（頁面入口不必改 HTML）；改完 JS 執行 `npm run build` 並提交 `static/dist` | `test_all_js_loaded_by_index` / `esm_link.test.js` 會抓沒被任何頁面載入的檔案；CI / Quality 會抓 dist 沒重建 |
| 新測試 | `tests/<對應檔>.py`；結構防回歸 → `tests/test_structure.py` | 新增測試檔要更新 `docs/單元測試維護文件.md` |

## 二、新增/修改內容 10 步檢查清單（寫完 code 前逐項對）

- [ ] **1. 放對位置**：對照上面的結構地圖。找不到合適位置 = 該開新檔，不是硬塞。
- [ ] **2. 同步掛載**：新 route → main.py import 行 + tuple **兩處**；新 JS → 由使用它的模組 import，並 `npm run build` 更新 `static/dist`；新 CSS → 各頁 link。
- [ ] **3. 權限**：新 write 端點——main.py tuple 內自動被 `require_login` 包（viewer 403 免自己加）；需要角色權限再掛 `require_perm("key")`。自我身份操作（改自己密碼）才用 `authenticate`。
- [ ] **4. 安全守則**（AGENTS.md 5 條）：JS 內插一律 `esc()`/`jsStr()`；qty ≥ 0（Pydantic ge=0 + 前端 clamping）；日期/時間格式驗證；匯出欄位過 `_safe()`；上傳副檔名白名單 + 大小上限；新增表單必填欄位前端驗證。違反會被 `test_security_regression.py` 擋。
- [ ] **5. dead code 4 步自查**（AGENTS.md）：新定義有引用？取代舊版 → 同 commit 刪舊版？搬移 → 清殘骸（含 import）？算好的數字 → 接 UI？
- [ ] **6. 測試同步**：行為改動 → 補斷言/測試，**且驗證「bug 版必紅」**（把 code 還原成問題版跑測試確認 FAIL，再還原——證明測試非自嗨）。純視覺 → 收尾紀錄標「不需測試」。
- [ ] **6A. No-op 先行**：批次/queue/scheduler 函式先處理空輸入；空工作必須在取得 DB、網路 client、檔案鎖或讀取專用 schema 前直接回傳明確的空結果，並以測試禁止對應 I/O。
- [ ] **7. 行尾對齊**：`git show HEAD:<file>` 實測 LF/CRLF，寫回對齊（改錯行尾 = 整檔假 diff）。
- [ ] **8. docs 同步**：新增/改行為 → 對應維護文件補說明（庫存操作 / 行事曆 / 權限 / 前端機制 / 安全性）；測試數變 → `單元測試維護文件.md`；架構變（新檔/新結構）→ `專案架構.md`。
- [ ] **9. 測試組別**：`./scripts/run-tests.sh [core|frontend|auth|rbac|regression]` 跑對應組全綠；大量修改才跑 `all`。
- [ ] **10. commit**：只 `git add` 自己改的檔（並行 agent 的檔不碰）；commit message 含 code + 測試 + docs 同一 commit。

## 五、改樣式 SOP（2026-09 CSS 架構重構後）

1. **先判斷範圍**：
   - 全站按鈕 / chip 的樣子 → 改 `3-components/button.css` / `chip.css`（全站同步，不必逐頁測）。
   - 某個共用元件（modal、表格、卡片）→ 改 `3-components/<元件>.css`。
   - 只有某一頁 → 在 `4-pages/<頁>.css` 用 `[data-page="<頁>"]` 覆寫，**不要改元件檔**，也不需要 `!important`。
2. **顏色 / 字級 / 圓角 / 字重 / z-index** 一律用 `tokens.css` 變數；要換品牌色只改 token 一處。
3. **新按鈕**直接套 `btn btn--<變體> btn--<尺寸>`；新篩選 / 頁籤套 `chip`；狀態 class 一律 `is-*`。
4. **送出前**跑：`pytest tests/test_css_architecture.py`（靜態規則）與 `bash scripts/run-tests.sh visual`（跨頁外洩、按鈕規格、互動）；需要對照截圖時用 `tests/visual/snapshot.py capture / compare`。
5. 詳細設計與原因見 `docs/CSS架構重構設計.md`。

# 🔐 權限列表（Permissions Catalog）

| | |
|---|---|
| **系統** | 振佳空調庫存管理系統（hvac-inventory） |
| **建立日期** | 2026-08-10 |
| **來源** | 由程式碼實際盤點核對（`main.py` + `app/routes/` 各 router 掛載的 `require_login` / `require_admin`） |

> **維護**：任何權限異動時，同步更新本文件與前端權限一覽（`static/js/permissions.js`）。

---

## 一、角色總覽

| 角色 | 說明 |
|---|---|
| 👑 **管理員（admin）** | 擁有系統**全部權限**（含使用者管理），負責帳號與系統維護 |
| 👤 **使用者（user）** | 可使用**全部庫存功能**（品項/出庫/盤點/整組/報表/照片）；**無法管理帳號** |
| 👀 **檢視者（viewer）** | **唯讀**：可看全部庫存資料、待領出/已領出清單、匯出 Excel；**所有寫入（新增/編輯/刪除/出庫/盤點/整組/照片）一律 403** |

權限由角色字串判斷：`admin`（全權）、`user`（庫存寫入但無使用者管理）、`viewer`（唯讀，寫入 method 全封鎖）。

## 三、使用者管理細項（第 8 項展開）

僅 admin 可使用，user 送 request 會得到 `403`：

| 功能 | 端點 |
|---|---|
| 查詢帳號列表 | `GET /api/users` |
| 新增帳號（可指定角色 admin/user/viewer） | `POST /api/users` |
| 批次新增帳號（表格一次多筆，逐列回報成功/失敗） | `POST /api/users/batch` |
| 修改角色／啟用停用 | `PUT /api/users/{id}` |
| 重設密碼 | `PUT /api/users/{id}/password` |
| 刪除帳號 | `DELETE /api/users/{id}` |

**保護規則**（已實作）：
- 不能刪除自己；不能停用最後一名啟用中的 admin
- 密碼以 PBKDF2-HMAC-SHA256（600,000 次迭代）儲存
- 連續 5 次登入失敗鎖定 15 分鐘

## 四、技術實作位置（給開發者）

- 登入守衛：`app/services/auth.py` — `require_login` / `require_admin`；**viewer 寫入封鎖就在 `require_login` 內**（`role == "viewer"` 且 method ∈ POST/PUT/PATCH/DELETE → 403），全站現在與未來的寫入端點自動被擋
- 路由掛載：`main.py:50-55`（9 個 router 全掛 `require_login`；`users` router 內各端點另掛 `require_admin`）
- 角色白名單：`app/routes/users.py` — `ALLOWED_ROLES = ("admin", "user", "viewer")`
- 批次新增 API：`app/routes/users.py` — `POST /api/users/batch`（逐筆建立、不回滾、逐列回報）
- 前端顯示條件：`static/js/auth.js`（admin 才顯示「👥 使用者」按鈕；viewer 依 `applyRoleView()` 隱藏新增/盤點/儲存列/提醒橫幅）
- 前端批次表格：`static/js/modals/users.js`（📋 批次新增收合區塊，一列一位使用者）
- 前端權限常數：`static/js/permissions.js` — 權限矩陣資料來源（`PERMISSION_MATRIX` / `getRolePerms`），使用者管理 modal 每列「📋 權限」按鈕展開該角色 ✅/🚫 清單

**未來方向**：若需細分權限（例如「唯讀角色」），升級為 RBAC（資料庫 permissions 表 + role_permissions 表），權限列表自動由系統產生，本文件可由 script 自動生成、不再手動維護。

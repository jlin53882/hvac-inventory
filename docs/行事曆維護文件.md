## 2. API 文件

### 2.1 行程（appointments）

| Method | 路徑 | 權限 | 說明 |
|---|---|---|---|
| GET | `/api/appointments?year=2026&month=8` | 登入 | 月曆資料（該月全部行程） |
| GET | `/api/appointments?date=2026-08-12` | 登入 | 當日行程清單 |
| POST | `/api/appointments` | `cal-mgmt` | 新增行程；同人同時段 → **409 衝突**；記錄 `created_by` |
| PUT | `/api/appointments/{id}` | `cal-mgmt` | 編輯（衝突檢查排除自己）；`created_by` 保留原值 |
| DELETE | `/api/appointments/{id}` | `cal-mgmt` | 刪除行程 |
| GET | `/api/appointments/export?date=2026-08-12` | 登入 | 匯出工程日報表 xlsx |

**POST/PUT body**：
```json
{
  "client_name": "陳先生 (B棟 3F)",   // 必填
  "address": "新北市板橋區…",          // 選填
  "service_type_id": 2,               // 選填（1=保養 2=維修 5=施工 6=場勘）
  "date": "2026-08-12",              // 必填
  "start_time": "09:00",             // 必填
  "end_time": "09:00",               // 選填（前端只填開始時間，end 自動 = start）
  "note": "備註",                     // 選填
  "user_ids": [1, 2]                 // 必填（至少一位負責人）
}
```

**回傳範例**（GET/POST/PUT）：
```json
{
  "id": 5, "client_name": "陳先生", "address": "…", "service_type_id": 2,
  "service_name": "維修", "date": "2026-08-12",
  "start_time": "09:00", "end_time": "11:00", "note": "…",
  "created_by": 1, "created_by_name": "管理員", "created_at": "2026-08-11 23:59:53",
  "user_ids": [1], "assignees": [{"id": 1, "name": "管理員", "color": "#1a73e8"}]
}
```

- `created_at` 為 **UTC**（前端轉本地顯示）
- `created_by_name`：新增者（UI 明細卡頂部橫條顯示；**不匯出到 Excel**）

## 3. Google 行事曆同步（完整說明）

### 3.1 架構

```
使用者(多人)               hvac FastAPI Server
──改行事曆──▶ appointments write (POST/PUT/DELETE) commit成功
                   │
                   ▼
       mark_sync_pending(appt_id, op[, map_rows])
                   │   [依指派人綁定的 gcal_key 解析目標 key 集合]
                   ▼
       appointment_sync_queue (appointment_id, key_id) 複合主鍵
                   ▲  每 5 分鐘掃 (debounce)
       sync_scheduler (background threading)
                   │
                   ▼
       gcal_sync: 對每個目標 key 各用該 key 的 Service Account
                   insert/patch/delete 到對應 calendar
                   + appointment_gcal_map (appointment_id, key_id)
                   │
                   ▼
       Google Calendar API (多行事曆)
```

### 3.2 方案 C：Service Account 管理

**家豪統建所有 Service Account，廠商只需做一件事——把 email 加入行事曆分享。**

- 同步方向：**單向**（本地 → Google，Google 端改動不回寫）
- Multi-Key：每把 key 對應一個廠商的 SA，同一行程可同步到多本行事曆
- 使用者綁 key：行程依指派人綁定的 key 決定同步到哪本行事曆

### 3.3 DB Schema

**gcal_keys（key 設定）**：
| 欄位 | 類型 | 說明 |
|------|------|------|
| id | INTEGER PK | 自增 |
| name | TEXT UNIQUE | key 名稱（如「廠商A」） |
| credentials_path | TEXT | Service Account JSON 檔路徑（相對路徑從專案根目錄算） |
| calendar_id | TEXT | 要寫入的行事曆 ID（`xxx@group.calendar.google.com`） |
| is_active | INTEGER DEFAULT 1 | 啟用/停用 |
| created_at | TIMESTAMP | 建立時間 |

**appointment_sync_queue（待同步隊列）**：
| 欄位 | 類型 | 說明 |
|------|------|------|
| appointment_id | INTEGER | FK → appointments |
| key_id | INTEGER | FK → gcal_keys（ON DELETE CASCADE） |
| op_type | TEXT | C=建立, U=更新, D=刪除 |
| google_event_id | TEXT | Google 端 event id（C/U 後回寫） |
| last_modified_at | TEXT | 最後修改時間（版本條件，防衝突） |
| attempts | INTEGER | 重試次數（≥5 停止） |
| last_error | TEXT | 最後錯誤訊息 |
| **PK** | | `(appointment_id, key_id)` |

**appointment_gcal_map（事件對映）**：
| 欄位 | 類型 | 說明 |
|------|------|------|
| appointment_id | INTEGER | FK → appointments（ON DELETE CASCADE） |
| key_id | INTEGER | FK → gcal_keys（ON DELETE CASCADE） |
| google_event_id | TEXT | Google 端 event id |
| data_hash | TEXT | MD5 hash（比對是否需要同步） |
| synced_at | TEXT | 最後同步時間 |
| **PK** | | `(appointment_id, key_id)` |

**users.gcal_key**：每位使用者綁定一把 key（name 字串），行程依指派人綁定的 key 決定同步到哪本行事曆。

### 3.4 同步機制

**mark_sync_pending**（`appointments.py`）：
- 行程 create/update/delete 成功後呼叫
- 依 `resolve_target_keys()` 解析目標 key 集合
- 每個目標 key 寫一列 `appointment_sync_queue`

**resolve_target_keys**（`gcal_sync.py`）：
- 查指派人員的 `users.gcal_key` → 找對應的 `gcal_keys.id`
- fallback：指派人沒綁 key 時，同步到**所有啟用 key**

**sync_scheduler**（background threading）：
- 每 **5 分鐘**掃描 `appointment_sync_queue`
- debounce：連續修改重置倒數，5 分鐘無修改才觸發
- 失敗重試：最多 5 次，超過放棄
- 全域開關：`gcal_sync_enabled = "0"` 時不執行

**sync_pending**（`gcal_sync.py`）：
- 速率限制：per-key 每分鐘 min(480, 8000/活躍key數) 次
- 冪等：C op 前先查 map（insert 成功但 map 寫入失敗時重試不重複）
- data_hash 快取：MD5 比對，hash 相同跳過同步
- 成功後寫回 `appointment_gcal_map` + 刪隊列（帶版本條件）
- 網路呼叫在交易外，不持 SQLite 寫鎖

### 3.5 前端設定頁

- **入口**：⚙️ 設定 → 📅 行事曆同步
- **Key 列表**：每個 key 有獨立滑動開關（啟停）+ 編輯 + 刪除
- **使用者綁 key**：下方區塊，為每位使用者選擇綁定哪把 key
- **全域開關**：panel 頂部，控制整個同步功能（關閉 = 🔴 同步已暫停）
- **行事曆行程卡片**：顯示 Google 同步狀態（✅ 已同步 / ⏳ 待同步 / ❌ 失敗）

### 3.6 建置步驟（新廠商）

1. **建 Cloud 專案**（只做一次）：Google Cloud Console → `hvac-calendar-sync` → 啟用 Calendar API
2. **建 Service Account**：憑證 → 服務帳號 → 下載 JSON → 放到 `secrets/`
3. **廠商操作**：把 SA email 加入行事曆分享（權限：查看事件）
4. **設定 hvac**：設定頁 → ＋新增 Key → 填名稱/JSON 路徑/calendar_id
5. **綁定使用者**：為每位使用者選擇綁定的 key

### 3.7 日誌

- 同步 log 輸出到 `logs/gcal_sync.log`（FileHandler）
- 輸出格式：`%(asctime)s [%(levelname)s] %(message)s`
- 來源：`sync_scheduler.py` + `gcal_sync.py` 雙 logger

### 3.8 Discord 失敗通知

同步失敗時自動發送 Discord webhook 通知到指定討論串。

- 設定：`.env` 的 `GCAL_SYNC_WEBHOOK_URL` + `GCAL_SYNC_THREAD_ID`
- 機制：`sync_scheduler.py` 的 `_notify_discord()`（fire-and-forget，失敗不抛異常）
- 觸發條件：`sync_pending()` 回傳 fail > 0
- 不通知：成功 / 無 due 項目 / webhook 未設定
- 訊息格式：`⚠️ hvac Google 同步失敗 成功 N / 失敗 M 時間：YYYY-MM-DD HH:MM:SS`

## 4. 匯出工程日報表

- 方式：`report.py` 以 openpyxl 載入 `app/assets/工程日誌範本.xlsx` → 填值 → BytesIO 回傳（**版面零寫死**，改格式只改範本檔）
- sheet 名 = `mmdd`；B 欄寬固定 **20**；縮放 130 分頁預覽
- **A2「工程師：藍政達 蘇昱豪」固定兩位**（2026-08-13 Sarah 指定）
- 每筆行程 → 區塊（最多 5 筆）：A=項次、B=時間（只填開始時間）、C=客戶、勾選欄 ✓、備註區第 1 列 `地址：xxx`（有填才顯示）、第 2 列備註
- 未使用區塊：全清空（避免殘留範本佔位）
- 公式注入防護：`_safe()`（= + - @ 開頭加撇號）

## 7. 故障排除

| 症狀 | 可能原因 | 解法 |
|------|----------|------|
| 同步後 Google 行事曆沒出現事件 | SA email 未加入行事曆分享 | 請廠商把 email 加入分享 |
| 同步後 Google 行事曆沒出現事件 | calendar_id 錯誤 | 到行事曆設定頁確認 ID |
| 同步失敗 403 | 廠商移除了分享 | 請廠商重新加回 email |
| 同步失敗 404 | calendar_id 格式錯誤 | 確認格式為 `xxx@group.calendar.google.com` |
| 新增 key 失敗 | name 重複 | 換一個名稱 |
| JSON 檔找不到 | 路徑錯誤 | 確認相對路徑從專案根目錄算 |
| 事件結束時間等於開始時間 | 前端只填開始時間 | 系統自動加 1 小時（build_event 兜底） |
| 同步一直失敗不消失 | attempts ≥ 5 | 查 `appointment_sync_queue` 的 `last_error`，修正後手動刪該列重觸發 |
| 行程卡片顯示 ❌ | 同步失敗 | 點卡片查看錯誤，常見 403（廠商移除分享）或 404（calendar_id 錯） |
| 同步 log 看不到 | logs/ 目錄不存在 | server 重啟會自動建 |

# 🛡️ 架構守衛與重構規範

> 建立於 2026-09-30（全專案維護性重構）。目的：把「重構時才想起來的規則」變成 **CI 會擋的測試**，
> 日後改 code 不必再靠記憶或整批重構補救。違反守衛時，請修 code，不要改測試（除非規則本身要調整，並在 PR 說明）。

## 一、守衛清單（測試檔 → 規則 → 違反時怎麼辦）

| 測試 | 規則 | 違反時 |
|---|---|---|
| `tests/test_architecture_guards.py` | ALL_CAPS 模組常數必須不可變（frozenset / tuple / MappingProxyType） | 改用不可變型別 |
| 〃 | `services` 不得 import `routes`（含函式內 lazy import） | 把共用邏輯放到 `app/services/` |
| 〃 | `routes` 之間不得互相 import | 同上 |
| 〃 | import 圖（含函式內延後 import）不得有循環；`gcal_sync` 不得 import `sync_scheduler` | 不可用「搬進函式裡」掩蓋循環：把依賴方向理順（下層不呼叫上層；需要通知上層時由上層傳 callback，或把入口放到上層），必要時才拆第三個模組 |
| 〃 | 上傳副檔名 / 大小上限只在 `services/upload_policy.py` 定義 | 引用 `upload_policy` |
| `tests/test_db_session.py` | `app/` 內只有 `database.py` 可以呼叫 `get_db()`（任何寫法都算，白名單 `NOT_MIGRATED` 目前為空） | 改用 `with db_session() as conn:` |
| `tests/test_inline_handler_ratchet.py` | 每檔 inline handler（`onclick=` 等）數量只准減少 | 新按鈕用 `data-action` / `addEventListener`；遷移後調降 BASELINE |
| `tests/test_frontend_state_ownership.py` | `appState` 欄位只准縮小；每個欄位只有指定的 owner 目錄可直接指派（`appState.X = …`）；已搬出的 feature 專用狀態不得回到 `core/state.js` | 單一 feature 專用的狀態放該 feature 的 `state.js` 或模組私有變數；確定跨 feature 共用才更新名單並註明原因 |
| `tests/test_frontend_assets.py` | features 內不得再手寫 `var xxxSeq = 0` 請求計數器 | 用 `core/request-guard.js` 的 `createRequestGuard()` |
| 〃 | features / core 不得再手寫 `xxxRequestSeq/Token` 計數器（模組層或狀態物件內） | 同上 |
| 〃 | 登入頁 / 權限頁不得註冊 401 handler；主頁 / 設定頁必須註冊 | 見 `pages/*.js` |

白名單（`NOT_MIGRATED` 等）只准縮小；項目修好後測試會要求同步移除。

## 二、共用工具

| 需求 | 用這個 | 位置 |
|---|---|---|
| 開資料庫連線 | `with db_session() as conn:`（離開必 close、例外先 rollback；**不自動 commit**） | `app/database.py` |
| 新增資料表欄位 | 在 `MIGRATIONS` 尾端加冪等函式（先 PRAGMA 檢查再 ALTER）；MIGRATIONS 每次啟動全部重跑，遷移必須永遠冪等（`SCHEMA_VERSION` 只是相容性標記 / 降版保護，不是遷移游標） | `app/db_migrations.py` |
| 種子資料 | `SEEDS`（順序 = 執行順序；RBAC 相容遷移須在預設矩陣之後） | `app/db_seeds.py` |
| 環境變數 | 一律經 `app/config.py`（`HVAC_LOG_DIR`、`HVAC_FRONTEND_SOURCE`、webhook）；import 不建目錄 | `app/config.py` |
| 新增上傳類型 | 建 `UploadResource` 設定 + `build_upload_router` | `app/services/upload_resource.py` |
| 照片 legacy 路徑 / 快取 | `photo_store` | `app/services/photo_store.py` |
| 前端「最新請求優先」 | `createRequestGuard()`：`next()` / `isCurrent(token)` / `invalidate()` | `static/js/core/request-guard.js` |
| 前端 401 轉登入 | `setUnauthorizedHandler(handleUnauthorized)`（頁面入口註冊；**不要覆寫 window.fetch**） | `core/api-client.js` |
| 測試隔離 DB / 全域狀態 | `isolated_db` fixture；autouse 已重設 IP 計數與照片快取；新增 process 全域時加進 `tests/conftest.py` | `tests/conftest.py` |

## 三、測試如何注入假連線

所有模組都已使用 `db_session()`，`NOT_MIGRATED` 白名單為空。測試需要假連線 / 追蹤 SQL / 注入「取得連線失敗」時，
請 patch **該模組的 `db_session`**（換成 `@contextmanager` 產生假連線或包裝真連線），例如 `tests/test_gcal_keys.py` 的
`traced_db_session`、`tests/test_gcal_sync.py` 的 `_patch_scheduler_db`；需要在測試裡直接開連線用 `from app.database import get_db`。
production 模組不得為了測試而重新匯出 `get_db`。

## 四、前端建置提醒

`static/dist` 有進 repo，CI 會檢查與原始碼一致。改了任何 `static/js/**` 請執行：

```bash
npm ci        # 第一次
npm run build
git add static/dist
```

## 一、角色總覽

| 角色 | 代號 | 說明 |
|---|---|---|
| 👑 **管理員** | `admin` | 系統全部權限（含使用者管理），負責帳號與系統維護 |
| 👤 **使用者** | `user` | 全部庫存功能（品項/出庫/盤點/整組/報表/照片）；**無法管理帳號** |
| 👀 **檢視者** | `viewer` | **唯讀**：可看全部庫存資料、待領出/已領出清單、匯出 Excel；**所有寫入一律 403** |

**新增帳號時的角色下拉**（單筆與批次）均提供這三種選項。

## 三、網頁操作：管理使用者（僅 admin）

### 3.1 入口
登入後 → 右上角「**👥 使用者**」按鈕 → 開啟「使用者管理」視窗。

### 3.2 新增單筆使用者
1. 填寫：**新帳號**、**密碼（至少 4 碼）**、**顯示名稱**（可空白）、**角色**
2. 按「＋ 新增」→ 列表立即更新
3. 帳號**不可重複**，重複會提示錯誤

### 3.3 批次新增多筆（表格方式）
> 適合一次開多個帳號（例如一次幫多位同事建帳號）。

1. 點「📋 批次新增（表格方式 · 一列一位使用者）」展開
2. 每列填：帳號／密碼／顯示名稱／角色
3. 「＋ 加一列」新增空列、「✕」刪除該列
4. 按「🚀 批次建立」→ **逐列回報結果**：
   - ✅ 綠標記 = 該筆建立成功
   - ❌ 紅標記 = 該筆失敗，右側顯示原因（例如「帳號已存在」）
   - 上方統計：`✔ 建 X 筆 / ✘ 失敗 Y 筆`
5. **成功的就保留，失敗的不回滾**——不會因為 1 筆錯誤就把 9 筆全取消

### 3.4 查看某位使用者的權限
1. 在使用者列表，該使用者的「角色」欄位下方點「**📋 權限**」
2. 展開該角色權限一覽：✅ 綠色 = 可用、🚫 灰色 = 禁用
3. 再點一次「📋 收起」即可收合

### 3.5 其他管理操作
| 操作 | 按鈕 | 說明 |
|---|---|---|
| 重設密碼 | 🔑 修改密碼 | 不需知道舊密碼 |
| 停用／啟用帳號 | ⏸ 帳號停用 / ▶️ 帳號啟用 | 停用後該帳號無法登入 |
| 刪除帳號 | 🗑 刪除帳號 | 不能刪除自己；不能停用最後一名啟用中的 admin |

## 四、權限怎麼被執行的（白話版）

| 層級 | 機制 | 效果 |
|---|---|---|
| **後端（真正的防護）** | 登入守衛 `require_login` 內檢查：角色為 `viewer` 且 HTTP 方法為 POST/PUT/PATCH/DELETE → 直接回 `403 檢視者僅能檢視` | **所有寫入端點自動被封鎖**，即使前端漏隱藏按鈕、或有人直接打 API，viewer 也寫不進去 |
| **前端（UX 防呆）** | viewer 登入時隱藏：＋新增、盤點頁籤、儲存列、盤點提醒橫幅、整組組裝/拆解、待領出操作欄；數量改純文字顯示 | 讓 viewer「看不到」不能做的操作，操作介面乾淨 |

**重點**：前端隱藏只是讓畫面乾淨，**後端 403 才是安全邊界**。viewer 就算手動呼叫 API 也會被擋。

## 五、使用者密碼與安全規則

- 密碼以 **PBKDF2-HMAC-SHA256（600,000 次迭代）** 儲存，資料庫不存明文
- 連續 **5 次登入失敗 → 鎖定 15 分鐘**
- 密碼最少 **4 碼**（既有規則，如需強化可調整）

## 六、開發者：權限異動維護 SOP

> 當要「新增一個角色」或「調整某角色的權限」時，依下列清單逐項修改，**避免改了程式碼卻漏同步文件**。

### 6.1 單一真源（Single Source of Truth）

權限資料以**兩處**為準，兩者必須同步：

| 真源 | 用途 | 檔案 |
|---|---|---|
| 後端角色白名單 | 建立/更新帳號時允許的角色 | `app/routes/users.py` 的 `ALLOWED_ROLES = ("admin", "user", "viewer")` |
| 前端權限矩陣 | 權限一覽 UI 顯示 | `static/js/permissions.js` 的 `PERMISSION_MATRIX` |

### 6.2 調整角色權限時的檢查清單

| # | 項目 | 位置 |
|---|---|---|
| 1 | 角色白名單（新增角色才需要） | `app/routes/users.py` → `ALLOWED_ROLES` |
| 2 | 後端寫入封鎖（viewer 專屬邏輯） | `app/services/auth.py` → `require_login` 內 method 檢查 |
| 3 | 前端權限矩陣（權限一覽顯示） | `static/js/permissions.js` → `PERMISSION_MATRIX` / `ROLE_LABELS` |
| 4 | 前端角色 UI 控制（隱藏按鈕/頁籤） | `static/js/auth.js` → `applyRoleView()` |
| 5 | 前端各頁渲染（卡片/整組/待領出） | `static/js/render/inventory.js`、`kits.js`、`prepared.js` 內的 `isViewer` 分支 |
| 6 | 角色下拉選項 | `static/js/modals/users.js`（單筆 + 批次 select） |
| 7 | 權限目錄文件 | `docs/權限列表.md` |
| 8 | 本文件 | `docs/使用者與權限維護說明.md` |
| 9 | 測試 | `tests/test_viewer.py`（403 封鎖）、`tests/test_users.py`（角色白名單）、`tests/test_frontend_assets.py`（前端資產） |
| 10 | 前端資源版本號 | `static/index.html` 全部 `?v=N` **加 1**（例如 `?v=16` → `?v=17`），避免瀏覽器快取舊版 |

### 6.3 修改後驗證

```bash
# 全量測試（含 viewer 403 封鎖、角色白名單、前端資產）
python -m pytest tests/ -q

# 手動確認（瀏覽器）
# 1. admin 登入 → 👥 使用者 → 新增 viewer 帳號 → 📋 權限 確認矩陣
# 2. viewer 登入 → 確認看不到新增/盤點/儲存列，匯出仍可用
# 3. 用瀏覽器 DevTools 直接打一個寫入 API（例如 POST /api/items）→ 應回 403
```

## 七、常見問題（FAQ）

**Q1：viewer 可以匯出 Excel 嗎？**
可以。家豪已拍板：viewer 可匯出 Excel、可看待領出/已領出清單（但不能操作）。

**Q2：viewer 看不到「盤點」頁籤，正常嗎？**
正常。盤點是寫入作業，viewer 被前端隱藏、後端也 403 雙重封鎖。

**Q3：批次新增有一筆失敗，其他筆會不見嗎？**
不會。逐筆建立、逐筆回報，成功的不回滾。

**Q4：我改了 permissions.js 但網頁沒變化？**
檢查 `static/index.html` 的版本號是否有 +1（§6.2 第 10 項），瀏覽器可能吃到舊快取。

**Q5：可以新增第四種角色嗎？**
可以，但需依 §6.2 檢查清單逐項處理（尤其後端 `ALLOWED_ROLES` 與 `require_login` 封鎖邏輯）。

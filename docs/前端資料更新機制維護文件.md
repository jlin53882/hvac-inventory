# 🔄 前端資料更新機制 維護文件

> 本文件說明網站**資料自動更新的行為**——何時會自動刷新、何時不會、為什麼「新增資料不會不見」。適用於所有前端頁面（單一庫存/待領出/已領出/盤點/整組/行事曆）。
> 建立：2026-08-14（多使用者即時性 Phase 3 機制盤點後定案）

---

## 一、重點結論（先記住）

| 問題 | 答案 |
|---|---|
| 網頁多久自動刷新一次？ | **沒有固定週期**——不會定時自動刷新 |
| 什麼時候會自動重載資料？ | **切回分頁**（visibilitychange）或**視窗聚焦**（focus）時，300ms 後重載 |
| 剛好在新增資料會不見嗎？ | **不會**——modal 開啟中自動重載會被跳過 |
| 有未儲存的數量調整會不見嗎？ | **不會**——`hasPending()` 有未存調整時自動重載被跳過 |

## 二、自動更新機制（實作位置：`static/js/app.js`）

### 觸發時機

```js
// app.js ~L215-230（2026-08-14 Phase 3 併發修復，Shell v2 後位移）
function autoReloadOnFocus() {
  if (hasPending()) return;                                  // ① 有未存調整 → 不重載
  if (document.querySelector('.modal-overlay.show')) return; // ② modal 開著 → 不重載
  if (document.visibilityState !== 'visible') return;        // ③ 分頁不在前景 → 不重載
  if (_focusReloadTimer) return;                             // ④ debounce 去重
  _focusReloadTimer = setTimeout(() => { _focusReloadTimer = null; loadData(); }, 300);
}
document.addEventListener('visibilitychange', autoReloadOnFocus);
window.addEventListener('focus', autoReloadOnFocus);
```

| 事件 | 觸發情境 | 行為 |
|---|---|---|
| `visibilitychange` | 分頁從背景切回前景（換分頁、切 App、開其他視窗後回來） | 300ms debounce 後 `loadData()` 重載全部資料 |
| `focus` | 瀏覽器視窗重新聚焦（點回視窗、從其他應用程式切回） | 同上（與 visibilitychange 共用 debounce，不會雙重載） |

### 行為細節

- **300ms debounce**（`_focusReloadTimer`）：兩個事件連續觸發只重載一次，不會閃兩次。
- **重載 = `loadData()`**：重新 fetch 當前頁籤的資料並重繪（非整頁 F5），畫面狀態（tab/site/月份）由 URL 參數保持（Phase 3 `syncViewUrl`）。
- **不重載的場景**（重要！）：
  1. **有未儲存的數量調整**（`hasPending()` 為真）——庫存頁 −/+ 改數量還沒按「儲存變更」
  2. **任何 modal 開啟中**（`.modal-overlay.show` 存在）——新增品項/派工/帳號、編輯、盤點輸入等
  3. **分頁不在前景**（`visibilityState !== 'visible'`）——例如切走後還沒切回來

## 三、為什麼「新增資料不會不見」（資料保護三層）

1. **modal 開啟中自動重載被跳過**（app.js L89）——你正在新增的表單輸入不會被重繪清掉。
2. **`hasPending()` 跳過**（app.js L88）——未儲存的數量調整不會因重載而錯位/遺失。
3. **M15 未存變更保護**（utils.js `_modalDirty`）——就算要關 modal，有變更會先 `confirm('有未儲存的變更，確定要離開嗎？')` 才關；儲存成功走 `closeModalForce` 跳過確認。

**已提交成功的資料**：存在 DB 裡，之後任何重載都只是重新顯示，**不可能消失**。

## 四、修改此機制的注意事項

- **新增任何「定時自動刷新」（setInterval）前先想清楚**：會與「modal 開啟中不重載」邏輯衝突——若加定時器，必須沿用 `hasPending()` + modal 檢查，否則使用者在編輯中資料會被清掉。
- **改 `autoReloadOnFocus` 的跳過條件**＝改「資料保護」邊界，動之前對照上面三層保護，缺一層就可能踩「輸入被清掉」的雷。
- **前端行為改動 → 同步補 `tests/test_frontend_assets.py` 斷言**（家豪規則）：目前機制有防回歸斷言（`hasPending`/modal 檢查在 app.js 的存在性斷言，見 `test_auto_reload_has_pending_guard` 等）。
- **修改後不用重啟 server**（static/ 即時讀檔 + mtime 版本號自動失效快取），但要確認 `curl /static/js/app.js` 已送新版。
- **桌面庫存/待領出/整組/盤點專用版面（2026-09-09）**：`app.js/switchTab()` 以 `inventory-content`、`prepared-content`、`kit-content` 控制 `.content` 寬度；`index.html` 載入 `style.inventory.css`、`style.kit.css`、`style.stocktake.css` 與 `style.stockout.css`，庫存篩選標題/低庫存缺貨 modal、整組 Dashboard、盤點 Dashboard 都是 page-scoped UI。所有新增 CSS 使用頁面前綴，避免改到 Sidebar/Navbar 或其他分頁。
- **KPI 清單資料一致性（2026-09-09）**：單一庫存 KPI、卡片、表格與 modal 共用 `getInventoryStatus(item)`；modal 由 `getFilteredInventoryItems()` 取得目前品牌/分類/搜尋結果，低庫存與缺貨不另打 API。待領出頁則沿用 `/api/prepared`、`preparedItems` 與既有 action handlers。
- **跨頁 KPI 呈現 contract（2026-09-11）**：inventory/prepared/stockout/stocktake/kits/signed-reports/quotation-upload renderer 的統計卡共用 `ui-kpi-*` class；`style.core.css` 以既有 `767px` breakpoint 同步 Desktop/Mobile 的 card、icon、value、label、context 小標，頁面 CSS 只保留欄數與 action/業務色彩語意。KPI 數值與 handler 來源不變。

## 五、常見問題

| Q | A |
|---|---|
| 為什麼別人新增的資料我要切分頁才看得到？ | 頁面開著不動**不會自動更新**（無定時器）；切分頁/聚焦視窗才觸發重載。若要多使用者「即時看到」，需加定時刷新（見注意事項）。 |
| 手機上也會自動刷新嗎？ | 會——切 App 再切回（visibilitychange）或點回瀏覽器（focus）都會觸發。 |
| 會整頁 F5 嗎？ | 不會——是 `loadData()` 重載資料重繪，不是整頁刷新。 |
| 我打到一半的字會不見嗎？ | 不會——modal 開著時自動重載被跳過（app.js L89）。 |

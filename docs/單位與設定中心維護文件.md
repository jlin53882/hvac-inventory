# 📦 單位動態清單 + 設定中心 維護文件

> 2026-08-16 家豪定案（C-3 分層權限 + B-1 設定全頁）。本文件為「單位」功能的唯一權威說明。

## 一、功能總覽

單位欄位從「寫死 select + 自由輸入框」改為**全站動態清單**：

- 4 個 modal（新增品項 / 編輯品項 / 非庫存已領出 / 非庫存待領出）單位欄統一為動態 `<select>`，資料源 `GET /api/units`
- UI 可直接新增單位（「＋」快速新增），新增後全站同步、免重整
- **modal 內就地快速新增（2026-08-16 晚接線，家豪選 B 變體）**：4 個 modal 單位下拉旁有「＋ 新增單位」連結（`openUnitQuickAdd()`，`item-mgmt` 才顯示），點開 → inline input + 新增/取消 → 成功後重填並選中；不需跳出 modal 去設定中心（原 dead code 接線）
- **🔍 單位搜尋框（2026-08-16 晚 UX 補強）**：4 個 modal unit select 上方有搜尋框（`filterUnitSelect()`，輸入即時過濾「包含」相似單位，清空還原全部；modal 重開自動清空）——單位多時用搜尋較快
- **⚠️ 重複單位提示（2026-08-16 晚）**：快速新增輸入已在清單的單位 → toast「⚠️ 單位「X」已存在」**不 POST**（`unitList.some` 檢查）
- 清單外的歷史值（如 `/4罐`、空字串）自動補「（歷史）xxx」選項，編輯舊品項不掉單位
- 歷史打錯值可**逐筆收編**（2026-08-16 方案 B：分組展開、每筆指定正確單位）或整組快速套用

## 四、收編語意（consolidate）

- `UPDATE items SET unit=?, updated_at=CURRENT_TIMESTAMP WHERE unit=?`——**含 `is_deleted=1` 幽靈品項**（非庫存出庫建的臨時品項，其單位也收編）
- 來源單位若在 `units` 表 → 自動停用（soft delete 保留歷史）
- **衝突防護**：items 唯一鍵 `(brand, COALESCE(code,''), name, unit, site)` 含 unit——收編前偵測同鍵已有目標單位品項 → 409 列出；`IntegrityError` 兜底 409（不會 500）
- **空字串可收編**：活庫曾有 11 筆 `unit=''`，`from_unit` 允許空字串（Pydantic Optional + 端點只擋 `to_unit`）
- **目標單位必須存在於 units 表**（`to_unit` 驗證，防收編出字典外孤兒值）
- 收編會 bump 全部該單位品項的 `updated_at`——正開著編輯 modal 的使用者儲存時會收到「已被他人修改」409（樂觀鎖正確行為）
- `GET /api/units/usage` 只統計 `is_deleted=0`（現行品項）——幽靈品項由 consolidate 一併處理，不列收編建議（刻意決策）

### 單筆收編（2026-08-16 方案 B：consolidate-item）

- 設定中心收編區改為**分組展開、逐筆指定**：每種歷史單位一組（「（空白）」× N 筆），點開顯示每筆品項（品名/數量），各自選目標單位 + 「改為」——處理完該筆即時消失（重拉 orphans），**免二次檢查**
- 資料源 `GET /api/units/orphans`：回傳 unit 不在**啟用**字典的每筆品項明細（`LEFT JOIN units ON unit=name AND is_active=1` → 語意＝「不在啟用清單」，停用字典單位的品項也會列出）——**含幽靈品項與 total_qty**
- `POST /api/units/consolidate-item`（unit-mgmt）：單筆 `{item_id, to_unit}`——item 不存在 404 / 目標不在字典 400 / 已同單位 400 / 同鍵已有目標單位活品項 409（單筆版 A3 衝突）/ IntegrityError 兜底 409 / bump updated_at
- **`new_qty`（2026-09-12 歷史分數轉換）**：`{item_id, to_unit, new_qty}` 同改總量——僅**單位置**品項可轉（多位置 400，總量語意不明）；數量變化寫 `movements`（reason「歷史單位轉換」）留軌跡；回傳含 `new_qty`
- **歷史轉換建議（2026-09-12，前端 `suggestQtyConvert`）**：僅 `/d + 純單位名`（如 `/4罐`）且總量明確時建議 `new = total/d`；`+` 混合、括號中文、空字串一律 ambiguous → 只給手填，不自動猜；寫入只在使用者按「套用建議」/「改為」確認後
- **不做來源停用**：來源若非字典值即無從停用；若為停用字典單位則早已停用（與整批 consolidate 的「收完自動停用」不同——整批的來源可能是啟用中的字典單位）
- 整批 `consolidate` 保留——組底「整組快速套用」直接複用它（confirm 二次確認，非預設操作）

## 五、設定中心（settings.html）

- 入口：topbar「⚙️ 設定」（顯示條件 `unit-mgmt || change-own-password`，實務上皆 admin）
- 桌面：左側清單（📦 單位管理 / 🔑 修改密碼）＋右側內容；手機：頂部 chip-bar 橫列切換（同帳號與權限頁模式）
- 「單位管理」面板：列表（↑↓ 排序、啟用開關）+ 新增輸入 + 歷史打錯值收編區（**分組展開手風琴**：組頭點擊展開 → 組內逐筆「— 請選擇 —」+「改為」；組底整組快速套用；全部處理完顯示「✅ 所有品項單位皆在清單中」）
- 「修改密碼」：**內嵌 changepw-modal 同款表單**（DOM id 一致，複用 `static/js/modals/changepw.js` 的 `submitChangePw`/`cpwCheckStrength`/`cpwResetChecks`——邏輯單一來源）
- 權限 gating：無 `unit-mgmt` 看不到「單位管理」左清單項與管理控制項（前端隱藏=UX 防呆，後端仍 403）

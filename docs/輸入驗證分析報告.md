## Tier A — 需要修復（影響資料正確性）

### A1. 編輯品項：low_stock 可輸入負數
- **位置**：`edit.js` L82 + `models.py` ItemUpdate
- **問題**：前端 `parseFloat(...) || 0` 無 ≥0 檢查；後端 `ItemUpdate.low_stock: Optional[float] = None` **無 ge=0 constraint**
- **證據**：`min="0"` 只在 HTML attribute（可被 DevTools 繞過）
- **衝擊**：低庫存警示值設為負數，導致警示邏輯永遠不觸發
- **建議**：
  - 後端：`low_stock: Optional[float] = Field(None, ge=0)`
  - 前端：`const ls = parseFloat(...); if (ls < 0) { toast('警示值不能為負數', 'error'); return; }`

### A2. 編輯品項：位置庫存 qty 可輸入負數
- **位置**：`edit.js` L87 + `items.py` update_item route
- **問題**：前端 `parseFloat(...) || 0` 無 ≥0 檢查；後端 `update_item` 處理 stocks 時直接 `float(s.get("qty") or 0)` **無 ge=0 檢查**
- **衝擊**：可在某位置輸入負庫存數量，導致總量計算異常
- **建議**：
  - 前端：每列 stock-qty 加 `parseFloat(qty) < 0` check
  - 後端：`update_item` 內 `new_qty = float(s.get("qty") or 0)` 後加 `if new_qty < 0: raise HTTPException(400, "庫存數量不能為負數")`

### A3. 編輯已領出：數量無上限驗證
- **位置**：`stockout.js` submitEditStockout L272-278 + `stockout.py` PATCH
- **問題**：前端只查 `!qty || qty <= 0`，無上限檢查；後端 `StockoutUpdate.qty: Optional[float] = None` **無 ge=0 constraint**
- **衝擊**：可將已領出數量改為極大值，觸發大量補扣庫存（或負庫存）
- **後端防線**：`_deduct` 有庫存不足守衛，但 `StockoutUpdate` 缺 ge=0
- **建議**：
  - 後端：`StockoutUpdate` 加 `qty: Optional[float] = Field(None, gt=0)`
  - 前端：加 `qty > record.delta * 2` 上限提示（防誤輸入）

## Tier B — 建議改善（UX / 一致性）

### B1. 新增帳號/批次新增/重設密碼：前端無密碼政策即時檢查
- **位置**：`perms.js` submitAddUser L328, submitResetPw L363
- **問題**：前端只檢查 `!password`（非空），不檢查密碼強度（8碼+大寫+小寫+數字）；後端 `_check_pw()` 有完整檢查
- **衝擊**：用戶輸入弱密碼 → 後端拒絕 → 只看到 generic error，不知具體原因
- **建議**：新增帳號/重設密碼時，前端呼叫 `pwPolicyMsg(password)` 即時顯示政策提示（與變更密碼 modal 一致）

### B2. 照片上傳：無前端檔案類型/大小驗證
- **位置**：`photo.js` uploadItemPhoto L47-51
- **問題**：前端直接 `fd.append('file', file)` 送出，無副檔名/大小檢查；`accept="image/*"` 只是 hint 不是 enforcement
- **後端**：✅ 有完整驗證（ALLOWED_EXT + 10MB + 40MP + corrupt check）
- **衝擊**：選錯檔案 → 後端拒絕 → 用戶才知失敗（UX 不佳但資料安全）
- **建議**：前端加 `file.size > 10*1024*1024` 和 `ALLOWED_EXT` 檢查，提前 toast 提示

### B3. 行事曆派工：date 欄位無前端必填驗證
- **位置**：`calendar.js` calSubmitAppt L119
- **問題**：前端只驗 `client_name`，不驗 `date`；HTML `<input type="date">` 預設今天（大多數瀏覽器），但技術上可清空
- **後端**：Pydantic `AppointmentIn.date: str` 為必填欄位
- **衝擊**：極端情況下 date 可能為空字串，後端會 reject
- **建議**：前端加 `if (!body.date) return showErr('⚠️ 請選擇派工日期')`

### B4. 新增品項：brand/code/location 未標示「選填」
- **位置**：`index.html` L107-147
- **問題**：HTML label 只有 "品名" 標為必填感（有 placeholder），brand/code/location/note 無「選填」標示
- **後端**：Pydantic `ItemCreate` 中 brand/code/note 有預設空字串
- **衝擊**：新用戶可能以為所有欄位都要填
- **建議**：在可選欄位旁加「選填」標籤或灰色 placeholder 提示

### B5. 編輯品項：name 空白時保留原值（無提示）
- **位置**：`edit.js` L75-80
- **問題**：`...(nameVal ? { name: nameVal } : {})` — 空白 name 不更新，但無 toast 提示「名稱未修改」
- **衝擊**：用戶可能忘記填 name → 送出後名稱沒變 → 以為是 bug
- **建議**：空白 name 時 toast 提示「名稱未修改（保留原值）」

- **位置**：`login.html` L250: `<form id="loginForm" autocomplete="on" novalidate>`

- **判定**：✅ 可接受

- **位置**：`stocktake.js` submitStocktake L232: `if (isNaN(v)) continue`

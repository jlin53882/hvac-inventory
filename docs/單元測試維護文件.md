## 二、怎麼跑（分組執行）

```bash
./scripts/run-tests.sh <組別>     # 開發中：只跑改動範圍
./scripts/run-tests.sh all       # commit/push 前：全量（建議加 -n auto 並行）
```

| 組別 | 內容 | 預估耗時 | 觸發條件（改到就跑這組） |
|---|---|---|---|
| `core` | test_main | ~61s | `app/routes/items`、`stockout`、`stocktake`、`kits`、`photos`、`stats`、`export.py` |
| `frontend` | frontend_assets + security | ~14s | `static/**` 任何改動；**新增任何後端端點**（XSS/公式注入守衛） |
| `auth` | test_users + test_viewer | ~64s | `app/routes/auth.py`、`users.py` |
| `rbac` | test_rbac + test_rbac_perms | ~47s | 權限系統、`app/database.py` seed |
| `regression` | test_v101 + appointments + gcal_sync + gcal_keys + deadvar_verify | ~28s | `appointments.py`、gcal 同步引擎（`gcal_sync.py`/`gcal_keys.py`/`sync_scheduler.py`）、v1.0.1 回歸 |
| `all` | 全部 | 串行 ~244s / **並行 ~44s** | commit/push 前必跑 |

**並行**：`env -u PYTHONPATH .venv/Scripts/python.exe -m pytest tests/ -q -n auto`（pytest-xdist 3.8.0，Windows 依核心數自動分派；測試已 tmp_path 隔離，並行安全）。

### ⚠️ 改到以下檔 = 一定要跑 `all`（所有測試的 fixture 底層）

`app/database.py`（schema/seed）、`app/services/auth.py`（hash/session/fixture 底層）、`main.py`（router 掛載）、`app/models.py`、`app/config.py`

## 三、測試架構與 fixture 模式（2026-08-14 優化後）

### 3.1 獨立 DB（每個測試隔離）
所有測試用 `tmp_path` + `monkeypatch.setattr("app.database.DB_PATH", str(test_db))`——每個測試獨立 SQLite，互不污染。

### 3.2 Session 注入（省 PBKDF2）
非登入測試的 admin fixture **不走 POST /api/auth/login**（每次 150ms PBKDF2 600k 迭代），改用：
```python
from app.services.auth import SESSION_COOKIE, create_session, init_admin_if_missing
init_admin_if_missing(_conn)
_token = create_session(_conn, admin_id)
c.cookies.set(SESSION_COOKIE, _token)
```
**登入/暴力破解測試保留真實登入**（test_users.py 的 rate-limit 等——它們就是要測登入）。

### 3.3 Module-scope 矩陣 fixture（test_rbac_perms）
80 個端點矩陣 case（viewer 403 + tech 白名單）是**唯讀檢查**，共用 module-scope fixture（`matrix_db`/`matrix_admin`/`matrix_viewer`/`matrix_tech`，整個 module 只建帳號登入一次）→ 129s → 29.5s。**狀態型測試**（覆蓋/保護規則/稽核）維持 function-scope 獨立 DB。

### 3.5 測試隔離教訓（2026-08-15）

**鐵則：任何測試不得在無 fixture 下使用 `TestClient`**——`with TestClient(app)` 會觸發 lifespan（`init_db` + `init_admin_if_missing`），若未 monkeypatch `DB_PATH` 就會打在正式 `inventory.db`。

真實案例：`test_users_requires_login` 原本無 fixture → 每次 pytest 連正式 DB（lifespan 建 schema/seed；若正式 DB users 表被清空會自動建 admin/admin123）。修法：加 `tmp_path, monkeypatch` + `monkeypatch.setattr("app.database.DB_PATH", str(tmp_path / "xxx.db"))`。

**防回歸測試**：`test_users_requires_login_does_not_touch_real_db` 斷言正式 DB 檔案 size/mtime 不變 + tmp DB 被初始化。

**commit 同步紀律**（v4 pro 審查 A1 教訓）：行為改動的測試必須**與 code 同 commit**——commit 與測試分離會讓 committed HEAD 無守護，CI/checkout 直接裸奔。

### 3.4 為何測試「慢」是故意的
登入驗證 PBKDF2-HMAC-SHA256 **600,000 次迭代 ≈150ms/次**——這是防暴力破解的安全設計，**絕不降低**（rate-limit 測試的慢是「該慢」）。加速靠 fixture 優化與並行，不靠弱化驗證。

## 四、新增功能的測試 SOP

### 4.1 新增 API 端點
1. 端點掛 `require_perm(key)`（RBAC）
2. **加入 `test_rbac_perms.py` 的 WRITE_ENDPOINTS 矩陣**（viewer→403 自動覆蓋）——新端點第一件事就是進矩陣
3. 寫該端點的功能測試（對應測試檔）
4. 跑 `./scripts/run-tests.sh frontend`（security 守衛）+ 相關組

### 4.2 新增前端（JS/HTML）
1. **使用者可控資料內插一律 `esc()` / `jsStr()`**（utils.js）
2. 跑 `./scripts/run-tests.sh frontend`——若掃描器列你的內插為「未審核」：安全（數字主鍵/常數三元）→ 加 `REVIEWED_SAFE_BODIES` 白名單**含註解**；否則補 esc()
3. 行為改動同步補 `test_frontend_assets.py` 斷言

### 4.3 修改既有功能
1. 找出對應測試檔 → 先跑該組（確認紅/綠基線）
2. 改完跑該組 + 受影響組（如改後端 API 回應形狀 → frontend 組也要跑，它斷前後端契約）
3. commit 前跑 `all`（並行 ~44s 很快，不用省）

## 六、疑難排解

| 症狀 | 原因 | 處理 |
|---|---|---|
| security 測試列「未審核內插」 | 新 JS 內插未審核 | 判斷安全（數字主鍵/常數）→ 白名單+註解；否則補 esc() |
| 並行測試偶發失敗 | xdist worker 間資源競爭 | 重跑確認；測試已 tmp_path 隔離，理論不互影響 |
| 改 database.py 後多組紅 | schema 影響所有 fixture | 正常——跑 `all` |
| Windows `pip` 命令被擋 | Hermes lifecycle_guard 讀污染 PYTHONPATH 炸 | 命令前加 `env -u PYTHONPATH` |

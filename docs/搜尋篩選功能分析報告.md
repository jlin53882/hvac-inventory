## 一、現狀盤點

### 1.1 搜尋功能（目前）

| 項目 | 說明 |
|------|------|
| **搜尋框位置** | topbar 內 `<input id="search-input">`（`type="search"`） |
| **搜尋邏輯** | 純前端 `renderInventory()` 內 `Array.filter()`，逐筆 `includes()` 比對 |
| **比對欄位** | `name`、`code`、`brand`、每筆 `stocks[].location`、`stocks[].note`（共 5 個欄位） |
| **觸發方式** | `oninput` → 800ms debounce → `renderInventory()` |
| **後端支援** | `GET /api/items?search=xxx` 支援 SQL LIKE 查詢同 5 欄位（`items.py:90-95`） |

**限制**：
- 搜尋是「全文模糊」= 輸入任何字會比對全部 5 欄位，**無法指定只搜品牌或只搜名稱**
- 品牌 tab 已存在（水平滾動 tabs），但**只能單選一個品牌**，不能多選
- **無「項目分類」欄位**（items 表無 category/type 欄位），品項只有 brand + name + code

### 1.2 品牌 tab（目前）

| 項目 | 說明 |
|------|------|
| **實作位置** | `static/js/render/inventory.js:4-25` `buildBrandTabs()` |
| **產生方式** | 從 `ALL_ITEMS` 計算每個 brand 出現次數 → 依數量排序 → 產生水平 tabs |
| **交互** | 點 tab → `currentBrand = b` → `renderInventory()` 重新渲染 |
| **active 樣式** | `.brand-tab.active` 深色背景 |
| **「全部」tab** | 固定第一個，計數 = 全部品項數 |

### 1.3 資料結構（DB 實際狀態）

**items 表欄位**：`id, brand, code, name, prepared_qty, unit, low_stock, is_kit, site, created_at, updated_at, is_deleted`

## 二、需求分析

家豪需求：「搜尋功能改成可以先篩選品牌 + 項目」

### 2.1 「項目」的可能含義

由於 DB 無 category 欄位，「項目」有兩種解讀：

| 解讀 | 說明 | 可行性 |
|------|------|--------|
| **A. 品項名稱關鍵詞分類** | 從 name 欄位提取共通詞（遙控器/基板/線圈/接觸器/管材） | ✅ 不需改 DB，前端分組 |
| **B. 新增 category 欄位** | 在 items 表加 category 欄位，前端維護分類 | ✅ 需 DB migration + 前端改 |

**推薦 A（前端分組）**：不需改 DB 結構，從現有品項名稱自動提取分類詞，維護成本最低。

### 2.2 改動範圍預估

| 改動項 | 檔案 | 說明 |
|--------|------|------|
| 篩選 UI | `static/index.html` | 新增品牌多選 + 分類篩選區 |
| 篩選邏輯 | `static/js/render/inventory.js` | `renderInventory()` 加多條件過濾 |
| 品牌多選 | `static/js/render/inventory.js` | `buildBrandTabs()` 改為可多選 |
| CSS 樣式 | `static/css/style.core.css` | 篩選區樣式 |
| 後端（可選） | `app/routes/items.py` | 若需 server-side 篩選加參數 |

## 三、建議方案

### 方案 A：搜尋區下方加「篩選面板」（推薦）

**UI 結構**：
```
[🔍 搜尋名稱 / 型號 / 位置 / 備註…]  ← 現有搜尋框
┌─────────────────────────────────────┐
│ 品牌：[全部✓] [大金] [日立] [三菱]...  │  ← 多選 chips
│ 項目：[全部✓] [電子零件] [機械零件]...  │  ← 分類 chips
│              [清除篩選]  共 N 項        │
└─────────────────────────────────────┘
[品牌 tabs] ← 保留但改為輔助快速切換
```

**品牌 chips**：
- 點擊切換選取/取消（多選）
- 「全部」= 不限制品牌
- 顯示每個品牌的數量 badge
- 水平可滾動（品牌多時）

**項目 chips（自動分類）**：
- 從品項名稱提取關鍵詞自動分組
- 規則：名稱含「遙控器」→ 遙控器類、含「基板/控制」→ 電子零件、含「線圈/接觸器」→ 電氣配件、含「管/銅」→ 管材、含「劑/脂」→ 化學品、其他→ 其他
- 顯示每類數量

### 方案 B：改造現有品牌 tab 為多選 + 加分類 dropdown

- 品牌 tab 改多選（按住 Ctrl 或 toggle 模式）
- 搜尋框旁加一個分類 dropdown

**缺點**：dropdown 對手機不友善，且選了就看不到其他選項。

### 方案 C：左右分欄（桌面）/ 側滑面板（手機）

- 左側/側滑：品牌清單 + 分類清單（checkboxes）
- 右側/主區域：篩選結果

**缺點**：改動大，目前 267 筆不需要這麼重的 UI。

## 四、實施建議（方案 A 詳細）

### 4.1 前端改動

1. **`index.html`**：搜尋框下方插入篩選面板 HTML
2. **`inventory.js`**：
   - 新增 `currentBrands = []`（空=全部）和 `currentCategory = '全部'`
   - `buildBrandChips()`：從 ALL_ITEMS 提取品牌 → 產生多選 chips
   - `buildCategoryChips()`：從 ALL_ITEMS name 提取分類詞 → 產生 chips
   - `renderInventory()` 加入多品牌 + 分類過濾邏輯
3. **`style.core.css`**：`.filter-panel`、`.filter-chip`、`.filter-chip.active` 樣式

### 4.2 後端（可選但推薦）

加 `categories` query param 支援 server-side 篩選（為未来 API 消費者預留）。

### 4.3 自動分類規則（前端）

```javascript
function inferCategory(item) {
  const name = (item.name || '').toLowerCase();
  if (/遙控|遙器|控制器|線控/.test(name)) return '遙控器';
  if (/基板|控制板|PCB|電路/.test(name)) return '電子零件';
  if (/線圈|接觸器|繼電器|開關|插座|斷路/.test(name)) return '電氣配件';
  if (/管|銅|鐵氟龍|配管/.test(name)) return '管材';
  if (/劑|脂|膠|發泡/.test(name)) return '化學品';
  if (/濾|網|棉/.test(name)) return '過濾耗材';
  if (/馬達|風扇|壓縮/.test(name)) return '動力設備';
  return '其他';
}
```

### 4.4 注意事項

- **「無廠牌」141 項 = 52.8%**：篩選時要考慮這群的處理（是否要顯示「無廠牌」chip）
- **品牌名不一致**：同一品牌可能有不同寫法（如 Panasonic vs 松下），需要 data normalization
- **效能**：267 筆全前端篩選無壓力，不需 lazy loading
- **保留品牌 tab**：篩選面板是加強，不是取代現有 tab（tab 做快速切換，panel 做精細篩選）

## 六、結論

1. **現有搜尋**已經很完整（5 欄位模糊搜尋 + 品牌 tab），但缺少「多品牌篩選」和「項目分類」
2. **推薦方案 A**：搜尋框下方加篩選面板（品牌 chips + 分類 chips），不改 DB 結構
3. **「項目」分類**從品項名稱自動提取關鍵詞分組，不需新增 DB 欄位
4. **改動量中等**：主要改 inventory.js + HTML + CSS，後端 optional
5. **需要家豪確認**：「項目」具體指什麼？是品項名稱分類、還是另有含義？

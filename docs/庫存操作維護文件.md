## 二、品項管理（items）

> 2026-08-16：**單位改為動態清單**——新增/編輯/非庫存已領出/非庫存待領出 4 個 modal 的單位欄統一為動態 `<select>`（資料源 `/api/units`，`static/js/units.js` 填充）；清單外的歷史值自動補「（歷史）xxx」選項不丟資料；「＋」快速新增＝有 `item-mgmt` 權限即可（admin/user）。管理入口：Sidebar/Header「⚙️ 設定」→ 設定中心「單位管理」（`unit-mgmt`，admin 專屬）——停用/排序/歷史打錯值收編。詳細見 `docs/單位與設定中心維護文件.md`。

- 品項屬性：廠牌（必填）、名稱（必填）、型號（必填）、位置（必填）、單位；**soft-delete**（`is_deleted` 標記，稽核流水不滅）
- **必填欄位（2026-08-25）**：新增品項時廠牌、型號、位置不可空白（前端 toast 提示）；後端 Pydantic `ItemCreate` 允許空字串（向前相容），但前端已改為必填
- **位置格式（2026-09-06）**：UI 改為兩段式輸入——「櫃子」下拉（編號A~F/鐵架/二樓）+ 「位置」文字輸入（如 1-1），組合成 `櫃子 | 位置` 字串存入 DB。舊資料（無 `|` 分隔）仍正常顯示
- **數量驗證（2026-08-25）**：所有庫存數量（stocks.qty / low_stock）≥ 0（Pydantic ge=0）；編輯已領出數量 > 0（gt=0）
- 數量以「位置庫存」為單位（item_stocks 一位置一列）；**數量調整一律走 ± 調整**（不能直接改庫存值）
- 搜尋：名稱/型號/廠牌；庫存頁有「缺貨」篩選
- **效能（2026-08-15）**：`GET /api/items` 已優化為一次批量查位置庫存（`WHERE item_id IN (...)` 分批 500/組）+ 一次 `listdir` 快取照片狀態——消除 per-item N+1。API 回應形狀不變，前端/匯出不受影響。

## 三、出庫作業（stockout）

- **直接出庫**：品項頁「🚚 已領出」→ 選數量/領出人 → 扣減庫存寫流水
- **待領出**：品項頁「📤 待領出」→ 鎖定數量 → 之後可「領出」或「退回」
- **退回**：已領出/待領出皆可退回（數量加回）
- **非庫存品項**：待領出/已領出頁可新增非庫存項目（不入庫存表）；**清單 site 過濾例外**——非庫存品項（is_deleted=1）不分 site 永遠顯示（`list_prepared`/`list_stock_outs` 的 site 條件含 `OR is_deleted = 1`；2026-08-16 修復：待領出原本 `AND site=?` 會擋掉非庫存，僅「全部」分片看得到）
- **非庫存 ⋯ 選單（2026-08-16 晚）**：待領出手機卡 ⋯ 選單對非庫存品項有效（`openPreparedSheet` 用 `preparedItems` fallback——`ALL_ITEMS` 不含 is_deleted=1 幽靈品項）；**非庫存無「退回」**（無庫存可回），選單/桌面按鈕只留「已領出 + 刪除」（手機 `if (!item.is_deleted)`、桌面 `${i.is_deleted ? '' : ...}`）
- **手機卡待領出 chip 佈局（2026-08-16 晚 V1b）**：「待領出」chip 移出品名行（名稱行只留品牌+名稱+非庫存 tag；型號/位置/chip/庫存全放品名下面）——`.m-card .nm` 是 nowrap+ellipsis，chip 塞名稱行會被長名截出誤導 ⋯（家豪實測回報）
- 併發防護：扣減採**守衛式原子 UPDATE**（`WHERE qty>=?`）——併發不超賣、不負庫存

### API

| Method | Path | 權限 | 說明 |
|---|---|---|---|
| POST | `/api/stockout` | stockout | 直接出庫 |
| POST | `/api/stockout/nonstock` | stockout | 非庫存出庫 |
| GET | `/api/stockouts` | prepared | 已領出流水（按日分組） |
| POST | `/api/stockouts/{id}/return` | stockout | 已領出退回 |
| PATCH | `/api/stockouts/{id}` | stockout | 編輯流水 |
| DELETE | `/api/stockouts/{id}` | stockout | 刪除流水（數量加回） |
| POST | `/api/prepare/nonstock` | stockout | 待領出新增非庫存項 |
| GET | `/api/prepared` | prepared | 待領出清單 |

## 四、盤點作業（stocktake）

- 盤點：選位置 → 輸入實際數量 → 提交 → 差異自動調整庫存 + 寫盤點紀錄
- **留空 = 確認**（2026-09-06）：實際數量留空表示與系統數量相同，提交時視為確認（diff=0）；填入與系統相同的數量也會送出（記錄盤點紀錄）
- 盤點輸入表分「🔧 整組」「📦 單一材料」兩個 tab（2026-08-13 Sarah 定案）：整組盤整組本身、單一材料盤一般品項
- 盤點表品項列顯示**圖片縮圖**（2026-08-16 家豪需求）：有照片顯示 `/uploads/{id}.jpg` 縮圖（點擊放大），無照片顯示 📷 佔位（`.cphoto` 樣式，與整組庫存頁表格同款）
- 整組 tab 展開**組成品項**（2026-08-16 家豪需求）：每個材料顯示縮圖+名稱+型號+「需 N ・ 系統 M 個」，且**每個組成品項也可輸入實際數量**（key=`itemId:location`，與單一材料盤點同一機制；後端 `POST /api/stocktake` 原本就支援材料 item_id+location，零後端改動）
- 歷史盤點：`/api/stocktake/dates` 列日期、可看每次差異明細
- **月底盤點提醒**（2026-09-06）：每月 25-31 日顯示提醒橫幅；**25-31日其中一天完成盤點後，當月不再顯示提醒**（localStorage 追蹤 `lastStocktakeMonth`，下個月 25 日再次顯示）

### API

| Method | Path | 權限 | 說明 |
|---|---|---|---|
| POST | `/api/stocktake` | stocktake | 提交盤點（差異調整） |
| GET | `/api/stocktakes` | 登入 | 盤點紀錄 |
| GET | `/api/stocktake/dates` | 登入 | 盤點日期清單 |

## 五、整組（kits）

- 整組 = 套件：一個主品項（item_id）+ 材料清單（kit_items：品項 + 需要量）
- **組裝**：材料足夠 → 扣材料庫存 → 主品項 +1（組數）
- **拆解**：主品項 -1 → 材料庫存加回
- 2026-08-13（晚間批次）：整組卡片也有「📤 待領出 / 🚚 已領出」按鈕（複用單一庫存 modal，用 kit 的 item_id）

### API

| Method | Path | 權限 | 說明 |
|---|---|---|---|
| GET | `/api/kits` | kit-view | 整組列表 |
| POST | `/api/kits` | kit-mgmt | 建立整組 |
| PUT | `/api/kits/{id}` | kit-mgmt | 編輯整組 |
| DELETE | `/api/kits/{id}` | kit-mgmt | 刪除整組 |
| POST | `/api/kits/{id}/assemble` | kit-mgmt | 組裝（扣材料） |
| POST | `/api/kits/{id}/disassemble` | kit-mgmt | 拆解（還材料） |

## 六、照片（photos）

- 照片存 `static/uploads/<item_id>.jpg`；**公開路徑 `/static/uploads/*` 一律 404**；登入者走 `/uploads/<int>.jpg`（檔名白名單 `\d+\.jpg` 防路徑穿越）
- 像素上限 40MP（load 前檢查，超限 400）
- 照片含個資 → **禁止 commit/push**（.gitignore 已排除）

### API

| Method | Path | 權限 | 說明 |
|---|---|---|---|
| POST | `/api/items/{id}/photo` | photo | 上傳/覆蓋照片 |
| DELETE | `/api/items/{id}/photo` | photo | 刪除照片 |
| GET | `/uploads/{id}.jpg` | 登入 | 讀照片 |

## 八、常見問題

| 症狀 | 原因 | 處理 |
|---|---|---|
| 數量調整被拒 | delta 使庫存 < 0（負庫存防護） | 先退回/盤點補正再調整 |
| 組裝失敗「材料不足」 | kit 材料庫存不夠 | 檢查材料位置庫存（整組頁顯示需量/現有量） |
| 併發出庫超賣 | — | 不會發生（守衛式原子 UPDATE）；若發生檢查是否繞過 API 直改 DB |
| 照片讀不到 | 檔名非純數字 / 未登入 / 檔案不在 | 確認 `static/uploads/<id>.jpg` + 登入 + 純數字檔名 |
| 匯出缺資料 | site 參數錯（office/warehouse） | 確認帶正確 site |
| 待領出數量與庫存不同步 | 手動直改 DB 或歷史資料 | 用盤點校正 |
